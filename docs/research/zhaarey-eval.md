# zhaarey/apple-music-downloader — engine evaluation for Waves

Research for [wayfinder ticket #3](https://github.com/ranokay/waves/issues/3). Companion to the gamdl evaluation. All claims checked against the repo clone (HEAD `0d895e0`, 2026-08-21), the GitHub REST API, and the WorldObservationLog/wrapper repo on 2026-09-01.

## Bottom line

**Fit-for-purpose technically: yes, the strongest Apple Music engine candidate. Fit-for-AGPL as vendored code: no — the repo has no license at all** ([`license: null` via API](https://api.github.com/repos/zhaarey/apple-music-downloader), [no top-level LICENSE file](https://github.com/zhaarey/apple-music-downloader); only [utils/runv2/LICENSE](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/runv2/LICENSE), an MIT notice for a vendored streaming-decryption lib). It covers every Waves requirement — ALAC up to 24/192, independent Dolby Atmos (EAC-3), LRC + TTML lyrics incl. translations/transliterations, 5000×5000/original cover art, catalog search — and it is actively maintained (473 commits since 2024-03, latest 2026-08-21; its decryption wrapper updated 2026-09-01). Recommended posture: **invoke it as an external, user-installed CLI (same pattern as the accepted "one-time external setup" constraint), never vendor or fork its code**, and keep gamdl as the fallback. If deeper integration is ever wanted, first ask the maintainer to relicense under AGPL-3.0.

## Dimensions

### 1. Auth + decryption requirements

- **Downloader (Go, single binary / `go run`)**: the catalog `authorization-token` is fetched automatically by scraping `music.apple.com`'s JS bundle for the JWT ([utils/ampapi/token.go](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/ampapi/token.go), [config.yaml.example:2](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)). The user does not need to supply it.
- **`media-user-token`** (browser-cookie value) is required for **lyrics, `aac-lc`, and MV** ([README §"Getting media-user-token"](https://github.com/zhaarey/apple-music-downloader#getting-media-user-token-for-lyrics), [config.yaml.example:1](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)). This is the one semi-manual, periodically-rotating credential. It can be **auto-derived** from the wrapper's account-info service by setting `get-account-from-device: true` ([config.yaml.example:27](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example), [README feature 7](https://github.com/zhaarey/apple-music-downloader#-special-update) — added in the latest commit ["add auto get music-token"](https://github.com/zhaarey/apple-music-downloader/commit/0d895e0)).
- **Decryption is delegated to a separate process: [WorldObservationLog/wrapper](https://github.com/WorldObservationLog/wrapper)** (MIT-licensed, actively pushed). It must be running before the downloader starts ([README prerequisites](https://github.com/zhaarey/apple-music-downloader#️-prerequisites)). Wrapper logs in once with `--login user:pass`, may prompt for a 2FA code, caches account info, and serves four local ports: sample decryption (10020), m3u8 URLs (20020), account info (30020), and the new template/key server (40020) ([Wrapper-SETUP.md](https://github.com/zhaarey/apple-music-downloader/blob/main/Wrapper-SETUP.md)). Account info is cached after login ("account info cached successfully"), so it is a **one-time setup per account, not per-session**, modulo Apple session expiry. A faster "template-decrypt" mode decrypts locally using the 40020 key server ([README §Local Template Decryption](https://github.com/zhaarey/apple-music-downloader#-special-update), merged PRs [#122](https://github.com/zhaarey/apple-music-downloader/pull/122), [#123](https://github.com/zhaarey/apple-music-downloader/pull/123), [#124](https://github.com/zhaarey/apple-music-downloader/pull/124)).
- **Platform support**: the downloader is Go — cross-platform. The wrapper is the constraint: it runs Apple's FairPlay stack (`libCoreLSKD`) inside an Android guest. Released binaries are `x86_64` and `arm64` ([releases page](https://github.com/WorldObservationLog/wrapper/releases)); the arm64 build is PRoot/Termux-oriented ([release notes](https://github.com/WorldObservationLog/wrapper/releases/tag/wrapper.arm64.latest)). The documented setup targets **Linux x86_64** ([Wrapper-SETUP.md](https://github.com/zhaarey/apple-music-downloader/blob/main/Wrapper-SETUP.md)). For **macOS Apple silicon**, realistic paths are Docker linux/amd64 under Rosetta or the arm64 build in a VM; Apple Silicon support is real but fragile — open issue [#61](https://github.com/WorldObservationLog/wrapper/issues/61) reports a QEMU signal-11 crash right after 2FA on an M2 under Docker/Rosetta, and PR [#59](https://github.com/WorldObservationLog/wrapper/pull/59) ("Docker-backed macOS launcher") was closed without merge. The newer wrapper-lite lineage bundles QEMU launchers for Linux/macOS/Windows/Android ([wrapper README](https://github.com/WorldObservationLog/wrapper)) with `hvf` acceleration on macOS, **but zhaarey's downloader is not compatible with wrapper-lite's single-port (12340) API** — no reference in the codebase; it speaks the 4-port protocol only.
- **Waves verdict on auth**: acceptable under the settled constraints (one-time external setup), but it means shipping instructions for: wrapper binary + login + 2FA + MP4Box ([README prerequisites](https://github.com/zhaarey/apple-music-downloader#️-prerequisites)) — more moving parts than any TIDAL-side equivalent.

### 2. Audio quality tiers & independent Atmos

- Formats table: `alac` (audio-alac-stereo), `ec3` (audio-atmos / audio-ec3), `aac`, `aac-lc`, `aac-binaural`, `aac-downmix`, plus MV ([README §Supported Audio Formats](https://github.com/zhaarey/apple-music-downloader#-supported-audio-formats)).
- ALAC ceiling configurable via `alac-max: 192000` (192/96/48/44.1 kHz) ([config.yaml.example:35](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)) — 24-bit/192 kHz hi-res is first-class (the README even uses a "Hi-Res Lossless 24-bit/192kHz" playlist as an example).
- **Dolby Atmos is fetched independently of stereo**: dedicated `--atmos` mode selects `ec-3`/`audio-atmos` HLS variants, with its own `atmos-max` (2768 or 2448 kbps, 16-channel E-AC-3) and its own save folder ([main.go:2012, 2409, 2572-2656](https://github.com/zhaarey/apple-music-downloader/blob/main/main.go), [config.yaml.example:17,36](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)). `--debug` prints per-quality availability (stereo/hi-res/Atmos) ([main.go:2553-2633](https://github.com/zhaarey/apple-music-downloader/blob/main/main.go)). This directly satisfies the "Atmos independently of stereo" constraint.

### 3. Lyrics

- Source is Apple's TTML via `amp-api …/songs/{id}/lyrics` or `/syllable-lyrics` ([utils/lyrics/lyrics.go:53-79](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/lyrics/lyrics.go)).
- `lrc-format: lrc | ttml` — raw TTML passthrough **or** conversion to LRC ([lyrics.go:41-51](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/lyrics/lyrics.go)). The LRC converter handles three TTML timing modes: word/syllable timing (enhanced LRC with `<mm:ss.xx>` per-word tags), line timing, and unsynced "None" ([lyrics.go:125-148, 255-286](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/lyrics/lyrics.go)).
- **Translations and transliterations** are extracted from TTML `iTunesMetadata` and emitted as extra LRC lines ([lyrics.go:177-249](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/lyrics/lyrics.go)); pronunciation-lyrics setup is documented as beta ([README](https://github.com/zhaarey/apple-music-downloader#-getting-translation--pronunciation-lyrics-beta), PRs [#66](https://github.com/zhaarey/apple-music-downloader/pull/66), [#75](https://github.com/zhaarey/apple-music-downloader/pull/75)).
- `embed-lrc` and `save-lrc-file` are independent toggles ([config.yaml.example:6-7](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)).
- **Gap**: all of this requires `media-user-token` (see §1), so lyrics are the feature most exposed to token rotation; lyrics requests are also the ones cloud-IP blocks break first ([PROXY-SETUP.md:133](https://github.com/zhaarey/apple-music-downloader/blob/main/PROXY-SETUP.md)).

### 4. Cover art

- Default `cover-size: 5000x5000` (Apple's max for `{w}x{h}` templated URLs) and `cover-format: jpg | png | original` ([config.yaml.example:12-13](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)).
- `original` mode rewrites the thumbnail URL to the un-re-encoded CDN asset (`a5.mzstatic.com/us/r1000/0/...`) and infers the true extension, with a fallback to the 5000×5000 URL on non-200 ([main.go:376-433](https://github.com/zhaarey/apple-music-downloader/blob/main/main.go)). This satisfies "original/highest quality".
- Animated artwork is optional and needs ffmpeg ([config.yaml.example:9-10](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)). Artwork regressions have happened and were fixed: merged [#70](https://github.com/zhaarey/apple-music-downloader/pull/70); [#125](https://github.com/zhaarey/apple-music-downloader/pull/125)/[#126](https://github.com/zhaarey/apple-music-downloader/pull/126) (wrong cover on playlist tracks) were **closed unmerged** — worth a test before relying on playlist downloads.

### 5. Search

- Full catalog search against `amp-api.music.apple.com/v1/catalog/{storefront}/search` for `album`, `song`, `artist`, with paginated, arrow-key interactive selection and quality prompt ([README feature 6](https://github.com/zhaarey/apple-music-downloader#-features), [main.go:478-685](https://github.com/zhaarey/apple-music-downloader/blob/main/main.go), [utils/ampapi/search.go:55](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/ampapi/search.go)). URL/ID input remains fully supported. Storefront is configurable for search ([config.yaml.example:67-71](https://github.com/zhaarey/apple-music-downloader/blob/main/config.yaml.example)). This is at parity with what Waves wants beyond URL-only input.

### 7. License — AGPL-3.0 compatibility

- **`license: null` on the repo and no top-level LICENSE/COPYING file** ([repo API](https://api.github.com/repos/zhaarey/apple-music-downloader); verified in the clone via `git ls-files`). Default = all rights reserved: **copying, modifying, or redistributing the code is not licensed at all**, so Waves (AGPL-3.0) cannot vendor, fork, embed, or link it.
- The decryption dependency WorldObservationLog/wrapper **is MIT** ([wrapper README §License](https://github.com/WorldObservationLog/wrapper#license)) — the blocker is specific to the downloader repo.
- (MIT-licensed vendored piece inside the downloader: [utils/runv2/LICENSE](https://github.com/zhaarey/apple-music-downloader/blob/main/utils/runv2/LICENSE), Sendy McSenderson.)
- The `main` Go module is literally named `main` ([go.mod](https://github.com/zhaarey/apple-music-downloader/blob/main/go.mod)) — it isn't importable as a library anyway; the only sane integration is subprocess invocation of a user-provided binary, which is consistent with mere-aggregation and the repo's own security posture (don't ship account-touching code inside Waves).

## Top three risks for Waves

1. **No license on the downloader repo (hard legal blocker).** All-rights-reserved by default: no vendoring, forking, or bundling, ever, unless the maintainer relicenses. The engine must stay an external, user-installed CLI that Waves merely invokes; a relicense request to zhaarey is the follow-up that would unlock deeper integration.
2. **Decryption stack is the weak link on macOS Apple silicon.** The wrapper (Android FairPlay guest) is documented for Linux x86_64; Apple silicon paths exist (arm64 release, Docker+Rosetta) but have open crash reports ([wrapper#61](https://github.com/WorldObservationLog/wrapper/issues/61)) and a rejected macOS-launcher PR ([#59](https://github.com/WorldObservationLog/wrapper/pull/59)). Waves' "macOS Apple silicon first" order makes this the biggest engineering risk; expect to also handle cloud-IP 503s via the proxy setting ([PROXY-SETUP.md](https://github.com/zhaarey/apple-music-downloader/blob/main/PROXY-SETUP.md)).
3. **Upstream churn with no releases.** Apple web-structure changes have repeatedly broken token scraping (#115/#90/#91) and decryption (#82/#94); there are no tags/releases to pin, the project has a two-person core (bus factor), and lyrics/aac-lc depend on a rotatable `media-user-token`. Waves must pin a commit, watch upstream, and ship an auto-update/pin-bump path for the engine.

## Fit-for-Waves verdict

**Adopt as the primary Apple Music engine, invoked as an external user-provided CLI — do not vendor.** It beats the alternatives on every functional dimension Waves cares about (ALAC 24/192 + independent Atmos + full-featured lyrics + original-quality covers + catalog search) and is under active maintenance as of this week. The license forces the subprocess/aggregation integration shape, which the settled constraints already permit; the decisive open question for implementation planning is packaging the wrapper login flow (credentials + 2FA) into a one-time setup experience on macOS Apple silicon.
